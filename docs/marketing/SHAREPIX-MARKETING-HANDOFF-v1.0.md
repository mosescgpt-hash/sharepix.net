## Task 1 — Keep guest pages out of search engines (privacy)

**Why:** a guest gallery showing up in Google is the worst-case privacy failure for this product.

1. Create `components/NoIndex.tsx`:

```tsx
import Head from "next/head";

export default function NoIndex() {
  return (
    <Head>
      <meta name="robots" content="noindex, nofollow, noarchive, noimageindex" />
      <meta name="referrer" content="strict-origin-when-cross-origin" />
    </Head>
  );
}
```

2. Render `<NoIndex />` on **every** guest-facing and host-private page from Task 0 #1: upload, gallery, slideshow, guest book, Moments, host dashboard, checkout success/cancel. **Don't** add it to the marketing pages or `/demo/*`.
3. If the site runs as SSR (not static export), also add a header in `next.config` for the same routes (adjust the patterns to the real routes):

```js
async headers() {
  return [
    { source: "/e/:path*", headers: [{ key: "X-Robots-Tag", value: "noindex, nofollow, noimageindex" }] },
  ];
}
```

4. **Robots.txt:** if any guest route is `Disallow`ed, Google can't crawl it, so it never sees the `noindex` tag. It can still list the bare URL if someone links to it. **Remove the guest gallery and upload routes from `Disallow`** in `build-seo-files.ts` so the `noindex` tag is seen. Keep `Disallow` for `/api`, admin and checkout.
5. **S3 photo URLs:** confirm guests only receive signed, expiring URLs. If any image is served from a public, permanent URL, report it. Don't change it in this task.
6. **Check:** fetch each guest route and confirm the robots meta tag is in the returned HTML.

Commit: `seo: noindex all guest and host-private pages`
